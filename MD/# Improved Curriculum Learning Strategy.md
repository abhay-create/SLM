# Improved Curriculum Learning Strategy for TinyStories SLM

## Executive Summary

The current curriculum learning implementation has **critical flaws** that undermine its effectiveness:

1. **Length ≠ Complexity**: Story token count is a poor proxy for linguistic difficulty
2. **Abrupt Transitions**: Fixed phase boundaries (30% → 60% → 100%) contradict gradual learning principles
3. **No Adaptivity**: Schedule ignores model's actual learning progress
4. **Missed Signal**: Ignores available linguistic complexity metrics
5. **Weak Evaluation**: Validation sampling doesn't measure curriculum-specific improvements

**Recommended Approach**: **Perplexity-Based Competence-Aware Curriculum** with smooth continuous scheduling.

---

## Current Approach Analysis

### What's Implemented
```python
# Three fixed phases based on story length
Phase 1 (0-25% training):    Top 30% shortest stories
Phase 2 (25-60% training):   Top 60% shortest stories  
Phase 3 (60-100% training):  Full dataset (100%)
```

### Critical Flaws

#### 1. Length is Not Complexity
**Evidence**: Recent research shows length-based curricula have uncertain effects on final quality and may only affect training stability, not model capabilities.

Example failure case:
- Story A: 50 tokens, complex syntax: *"Though exhausted, the cat, which had been hiding beneath the porch all morning, finally emerged."*
- Story B: 150 tokens, simple repetitive: *"The cat was happy. The cat played. The cat ran. The cat jumped..."*

Current approach ranks A as "easier" than B—this is backwards.

#### 2. Fixed Schedule Ignores Model Competence
The model may master 30% of stories in 10% of training, wasting 15% on redundant easy data. Conversely, it might struggle and need more time before advancing.

**From literature**: Competence-aware curricula that respond to the model's current performance ensure an optimal learning trajectory, while static schedules fall short when model competence rapidly changes.

#### 3. Abrupt Phase Transitions
Jumping from 30% → 60% creates distribution shift. The model suddenly sees stories it's never encountered, potentially destabilizing training.

**Better**: Smooth continuous expansion proportional to validation loss improvement.

#### 4. No Multi-Dimensional Difficulty Assessment
TinyStories varies in:
- Vocabulary richness (type-token ratio)
- Syntactic complexity (clause depth, dependency structures)
- Narrative coherence (discourse markers, temporal structure)
- Semantic density (concept count, abstractness)

Length captures none of these.

---

## Literature-Backed Evidence

### What Works in Curriculum Learning for LMs

1. **Perplexity-Based Scoring** (CGLS, 2025)
   - Using a reference model to score perplexity of training examples before curriculum design achieved consistent gains, particularly on complex knowledge-intensive datasets
   - Small reference model scores each story's difficulty objectively

2. **Competence-Aware Scheduling** (CAMPUS, 2025)
   - Instead of fixing the order by a predefined metric, continually adjust which data the model sees next based on the model's current performance
   - Curriculum adapts: if model improves quickly, pace increases; if struggling, slows down

3. **Smooth Continuous Progression** (SPARD, 2026)
   - Self-paced curriculum by perceiving learning progress to dynamically adjust data importance, thereby synchronizing learning intent with data utility for optimal performance
   - Gradual difficulty curve, not discrete jumps

4. **Multi-Metric Difficulty** (Crossley et al., 2024)
   - Measuring linguistic complexity using a comprehensive set of indices of lexical richness, syntactic complexity, and discoursal complexity better captures text difficulty than surface features

### What Doesn't Work

**Length-only curricula**: Length-based curricula may affect stability with uncertain effects on final quality

**Fixed linguistically-motivated orderings**: Linguistically motivated orderings can show diminishing returns at scale when not adaptive.

---

## Recommended Strategy: Perplexity-Based Competence-Aware Curriculum

### Core Idea
1. **Pre-score stories** using a small reference model's perplexity (or build a composite difficulty score)
2. **Start with low-perplexity stories** (actually simple language)
3. **Gradually expand** the difficulty range based on validation loss improvement rate
4. **Adapt pacing** to model's current competence

### Why This Works for TinyStories + 50M Model

| Factor | Why It Matters |
|--------|---------------|
| **Dataset**: Constrained vocab, simple domain | Reference model perplexity reliably separates easy/hard within this domain |
| **Model size**: 50M params (not tiny, not huge) | Large enough to benefit from curriculum, small enough that training is tractable |
| **Synthetic data**: Generated by GPT-4 | Consistent quality, less noise than web scraping—curriculum signal is cleaner |
| **Rapid convergence expected** | Curriculum can frontload learning of core patterns, then expand to variations |

class CompetenceAwareCurriculum:
    def __init__(self, curriculum_scores, initial_fraction=0.15, max_fraction=1.0):
        """
        curriculum_scores: sorted array of (story_idx, difficulty, length)
        initial_fraction: start with easiest 15% of stories
        max_fraction: expand up to 100%
        """
        self.scores = curriculum_scores
        self.current_fraction = initial_fraction
        self.max_fraction = max_fraction
        
        # Competence tracking
        self.val_loss_history = []
        self.improvement_rate = 0.0
        self.patience_counter = 0
        
    def update_competence(self, val_loss):
        """Update curriculum based on validation loss."""
        self.val_loss_history.append(val_loss)
        
        if len(self.val_loss_history) < 3:
            return  # Need history to compute improvement
        
        # Compute improvement rate (recent vs older)
        recent_avg = np.mean(self.val_loss_history[-3:])
        older_avg = np.mean(self.val_loss_history[-6:-3]) if len(self.val_loss_history) >= 6 else recent_avg
        
        self.improvement_rate = (older_avg - recent_avg) / max(older_avg, 1e-6)
        
        # Adaptive expansion logic
        if self.improvement_rate > 0.01:  # Strong improvement (>1%)
            # Model is learning well → expand difficulty range faster
            expansion = 0.05
            self.patience_counter = 0
        elif self.improvement_rate > 0.001:  # Moderate improvement
            expansion = 0.02
            self.patience_counter = 0
        else:  # Stagnating
            # Don't expand yet—model needs more time on current difficulty
            expansion = 0.0
            self.patience_counter += 1
            
        # If stagnating for too long, force small expansion to avoid getting stuck
        if self.patience_counter > 3:
            expansion = 0.01
            self.patience_counter = 0
        
        # Update fraction with smooth growth
        self.current_fraction = min(
            self.current_fraction + expansion,
            self.max_fraction
        )
        
    def get_eligible_stories(self):
        """Return indices of stories within current difficulty range."""
        n_eligible = max(100, int(len(self.scores) * self.current_fraction))
        return self.scores[:n_eligible, 0].astype(int)  # Return story indices
